# ANYQ

Операционная система для торговли в Казахстане: касса, склад, закупки, кабинет
владельца и B2B-витрина заказов — одним приложением, которое ставится на обычный
телефон или планшет и работает без интернета.

Не для ресторанов. Ресторанный код в репозитории есть, он остался от прежней
версии и помечен как legacy; продукт делается для магазинов, складов, небольших
сетей и дистрибуции.

## На чём всё держится

Три решения, из которых следует почти всё остальное в коде:

**Журнал — это правда, остаток — кэш.** `StockMovement` только дописывается,
`Stock.quantity` пересчитывается из него. Любая цифра остатка обязана сходиться с
суммой своих движений, и это проверяется — тестами, командой резервного
копирования и утренней сводкой владельцу. Продукт, который не может доказать свои
числа, для учёта бесполезен.

**Пересчёт не закрывает магазин.** Инвентаризация применяет разницу, которую
насчитал человек, а сервер отматывает журнал к моменту пересчёта. Поэтому считать
можно при работающей кассе, а не ночью.

**Касса работает без сети неделю.** Продажи копятся в очереди и уходят сами.
Отсюда токен на тридцать дней, идемпотентность на всём, что двигает деньги и
товар, и отказ от многого, что требует постоянного соединения.

## Запуск на своей машине

```bash
docker compose -f docker-compose.dev.yml up -d   # Postgres на 5433
npm install
npm run db:migrate
npm run dev:api                                   # http://localhost:4000
npm run dev:pos                                   # касса
npm run dev:admin                                 # админка платформы
npm run dev:orders                                # витрина заказов и сайт
```

Если 4000 занят: `PORT=4010 npm run dev:api`, а в `apps/pos/.env` и
`apps/admin/.env` — `VITE_API_URL=http://localhost:4010`.

## Проверки

```bash
npm test          # 847 модульных, секунды, ничего не нужно поднимать
npm run test:db   # 331 интеграционный, нужен Postgres, около пяти минут
npm run onboard:check   # весь путь заведения магазина против живого сервера
npm run backup:verify   # копия снимается, разворачивается и сверяется
```

`onboard:check` намеренно отказывается работать против базы, где уже есть
компании: он создаёт компанию, а удалить её нельзя — маршрутов удаления нет, и
это не упущение.

## Как здесь принято писать

Комментарий объясняет, почему так, а не что делает строка. Если решение спорное —
в комментарии стоит альтернатива и причина, по которой её не выбрали. Тест,
который не падает, когда ломают то, что он охраняет, считается отсутствующим:
проверять это принято ломанием, а не верой.
